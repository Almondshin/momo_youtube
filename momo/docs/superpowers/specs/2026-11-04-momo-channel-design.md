# 모모타임 (MomoTime) — 이중 언어 동요 채널 운영 기획·요구사항

작성일: 2026-11-04

상태: 인터뷰를 반영한 검토용 설계 초안. 자동화가 구현되거나 예약 작업이 등록된 상태는 아니다.

브랜드 결정: **채널명 모모타임 · 영문 표기 MomoTime · 핸들 @MomoTimeSong**. 사용자는 핸들을 `@MomoTimeSong`으로 변경했다고 알렸다. 끝부분은 복수형 `Songs`가 아니라 단수형 `Song`이다. 채널 브랜드만 변경하고 토끼 모모는 유지한다. 외부 채널의 핸들 설정 상태는 사용자 보고에 근거하며, 이 문서 작성 과정에서 채널을 직접 변경한 것은 아니다.

## 1. 목적과 운영 목표

2~4세 아이들이 쉽게 따라 부르며 기초 단어를 접할 수 있는 동요를 제공한다. 한국어와 영어 콘텐츠를 하나의 **모모타임(MomoTime)** 유튜브 채널에 게시하고 언어별 재생목록으로 구분한다. 주인공은 기존 토끼 모모다.

아이들의 언어 학습, 다양한 국가의 시청자 확보, 수익 극대화가 사용자가 밝힌 목표다. 초기 수익 경로는 유튜브 광고를 중심으로 검토한다. 특정 조회수·매출·흑자 시점은 약속하거나 임의로 목표치에 넣지 않는다. 언어 학습 효과 역시 아직 검증된 성과가 아닌 콘텐츠 제작 목표다.

플랫폼 의존에 대한 사용자의 우려를 반영해 음원·영상 원본, 가사, 제작 이력, 이용 권리 기록을 보관한다. 음원 유통, 부모 대상 학습자료 판매, 별도 사이트나 앱은 향후 검토 대상으로 남긴다. 이번 범위에 자동으로 포함하지 않는다.

## 2. 사용자와 합의한 콘텐츠 기준

| 항목 | 결정 |
|---|---|
| 대상 | 2~4세 아이들, 쉽게 따라 부를 수 있는 동요 |
| 영어 | 기초 단어를 익히며 영어권 아이들도 함께 즐기는 콘텐츠 |
| 한국어 | 쉬운 말 배우기와 재미·흥겨움을 함께 중시 |
| 소재 | 단어 중심. 동물·색깔·숫자 등은 예시이며 특정 목록으로 제한하지 않음 |
| 학습 단어 수 | 한 단어 집중곡과 2~3개 단어를 다루는 곡을 혼합. 한 곡당 핵심 학습 단어 최대 3개 |
| 단어 수의 의미 | 가사 전체 어휘 수가 아니라 가르치려는 핵심 단어 수. 중심 단어가 분명해야 함 |
| 곡 길이 | 각 곡 1~2분 |
| 언어별 곡 | 한국어·영어는 서로 다른 곡이어도 됨. 동일 멜로디나 번안곡은 필수 아님 |
| 언어 쌍 | 같은 영상을 공유하는 한국어·영어 곡은 동일 주제와 대응하는 핵심 단어를 다룸 |
| 캐릭터·연출 | 기존 모모와 승인된 디자인을 유지. 춤·표정·사물과의 상호작용 중심 |
| 입모양 | 노래 가사에 맞춘 립싱크를 생략 |
| 채널 | 채널 하나, 한국어·영어 재생목록 분리 |

동요의 후렴·핵심 단어 반복과 영상 간 내용의 획일화는 구분한다. 같은 주제의 언어 쌍은 화면을 공유하지만, 새로운 주제에는 그 단어를 설명하는 장면·가사·곡 구성을 만든다.

### 추천안으로 채택할 화면 표현

사용자가 세부 선택을 추천에 맡긴 부분이다. 공통 영상 위에 해당 언어의 핵심 학습 단어를 **한 번에 하나씩 크게** 표시한다. 한국어 영상에는 한국어 단어, 영어 영상에는 영어 단어를 쓴다. 문장 전체 가사 자막은 기본 범위에 넣지 않는다.

기존의 상단 안전영역, 모모 얼굴을 가리지 않는 배치, 둥근 글꼴 등은 활용한다. 글자는 생성 이미지에 그려 넣지 않고 후편집으로 합성한다.

## 3. 제작량과 영상 공유의 의미

| 작업일 | 신규 노래 | 신규 공통 영상 | 최종 공개본 |
|---|---|---|---|
| 월요일 | 한국어 1곡 + 영어 1곡 | 두 곡이 공유할 영상 1편 | 한국어 1편 + 영어 1편 |
| 금요일 | 한국어 1곡 + 영어 1곡 | 두 곡이 공유할 별도 영상 1편 | 한국어 1편 + 영어 1편 |
| 주간 합계 | **4곡** | **2편** | **4편** |

‘영상 2편’은 5초짜리 생성 클립 두 개를 뜻하지 않는다. 각각 여러 컷으로 구성되는 주제별 공통 영상 두 편이다. 월요일과 금요일은 서로 다른 제작 묶음이며, 한 주 전체에 동일 영상 하나를 반복 사용하는 방식이 아니다.

한 제작 묶음은 `공통 주제·학습 단어 + 공통 영상 소재 + 한국어 곡 + 영어 곡 + 언어별 최종 출력`으로 관리한다. 두 언어를 위해 같은 장면을 각각 다시 생성하지 않는다. 최종 파일은 언어별 음원·화면 단어를 포함하므로 주 4개가 된다.

### 곡과 화면 길이를 맞추는 구현 원칙 — 설계 제안

독립적으로 만든 두 곡은 길이와 단어 등장 시점이 다를 수 있다. 공통 장면 원본을 재사용하면서 언어별 최종 조립에서 장면 길이·반복·단어 표시 시점을 맞춘다. 이것은 새 영상 생성 횟수를 늘리는 작업이 아니다. 같은 장면 원본을 사용하는 것이며 두 최종 파일의 모든 프레임 시각이 동일해야 한다는 제약은 두지 않는다.

학습 단어와 화면 속 대상이 어긋나거나 과도한 속도 변화가 필요한 경우에는 자동 검사를 통과시키지 않는다. 구체적인 장면 배치와 허용 범위는 샘플 검증으로 정하며, 원음을 무리하게 늘이거나 가사를 잘라 길이만 맞추지 않는다.

## 4. 실행 일정과 무인 운영

- 시간대: `Asia/Seoul`.
- 매주 월요일·금요일 **오전 9시에는 제작을 시작**한다. 오전 9시 공개를 약속하는 일정이 아니다.
- 자동 제작과 검사를 통과한 언어별 결과물은 완성되는 대로 업로드하고 공개한다. 별도의 고정 공개 시각은 없다.
- 실행 환경: 현재 Mac. 사용자는 작업 시작부터 완료까지 전원을 켜고 절전되지 않게 운영할 수 있다고 답했다.
- 정상 운영에서는 주제·가사 작성, 음원 생성·선택, 영상 제작, 검사, 업로드·공개에 매번 사용자 조작이나 승인을 요구하지 않는다.
- 자동화 활성화 시점은 아직 정하지 않았다. 연동 검증과 초기 설정을 완료한 후 활성화하며, 문서 작성 자체가 운영 시작을 의미하지 않는다.

예정 흐름:

> 정기 실행 → 주제·학습 단어 선정 → 두 언어 가사 작성 → Suno 음원 2곡 생성·검사 → 공통 영상 제작 → 언어별 조립·검사 → 유튜브 업로드·공개 및 재생목록 배치 → 결과 알림

예약 실행기, 작업 상태 보관 방식, 중복 실행 잠금, 렌더링 명령 등의 구체적인 구현은 담당자가 정한다. Mac이 꺼져 있거나 네트워크가 단절된 동안에는 작업 실행과 원격 알림을 보장할 수 없다. 복구 후 누락을 보고하고, 예산 확인 없이 밀린 작업을 한꺼번에 생성하지 않는다.

## 5. 도구와 비용 제약

1. **음원은 Suno로 고정한다.** 사용자는 로컬 ACE-Step 대체안을 제시받은 뒤 Suno 고정을 명시했다. 다른 음원 모델이나 사람이 곡을 전달하는 방식으로 임의 변경하지 않는다.
2. 영상은 현재 Higgsfield 구독 범위에서 제작한다.
3. 추가 크레딧 구매, 새 유료 서비스 가입, 별도 API 잔액 충전 없이 운영한다. 기존 구독료는 제작비에 포함한다.
4. 승인된 캐릭터 시트·고정 클립·음성 라이브러리는 재생성하지 않는다. 고정 음성 ID도 변경하지 않는다.
5. 기존 에피소드 150크레딧 상한을 높이지 않는다. 설계 제안으로는 공통 영상 제작 묶음에 비용을 한 번만 귀속하고, 두 언어 결과를 위해 이 상한을 두 배로 늘리지 않는다. 재생성 비용도 같은 예산에 포함한다.
6. 매 생성 전에 실제 모델 단가·남은 사용량·예상 소모량을 확인한다. 저장소의 과거 단가를 현재 가격으로 간주하지 않는다.
7. 일일 한도·권한 오류는 기존 규칙대로 중단한다. 추가 결제나 다른 과금 경로로 자동 우회하지 않는다.

인터뷰 중 확인한 Higgsfield 연결 계정은 Plus, 잔액은 1,210.37크레딧이었다. 이는 조회 당시 잔액이며 월 제공량이나 지속 가능한 주간 제작량을 의미하지 않는다. Suno 생성량·다운로드 허용량, Higgsfield 갱신 주기·월 제공량, 재시도 소모량을 별도로 확인해야 한다.

## 7. 자동 검사와 실패 처리 — 설계 제안

사용자는 정상 운영에서 개별 승인을 원하지 않는다. 기존 런북의 사람 승인 단계를 그대로 대기시키는 대신, 구현 시 자동 검사 결과를 별도로 기록하는 정책으로 바꿔야 한다. 자동 통과를 과거의 ‘사용자 승인’으로 허위 기록하지 않는다.

검사 범위는 다음과 같다.

- 가사: 언어, 2~4세 대상 표현, 핵심 학습 단어 1~3개, 같은 언어 쌍의 주제 대응, 원하지 않는 문구·기존 IP 참조 여부.
- 음원: 60~120초, 파일 손상·무음·클리핑, 목표 가사와의 대응 및 핵심 단어 발음, 과도한 간주 여부.
- 영상: 승인된 모모 디자인의 일관성, 대상 사물과 학습 단어의 대응, 글자 안전영역, 노래·장면·단어 표시 타이밍, 정상 재생 여부.
- 배포: 올바른 언어·제목·썸네일·재생목록, 아동용 설정, 중복 업로드 방지, 실제 공개 상태 확인.

수치 기준과 평가 도구는 구현 담당자가 샘플을 통해 정하고 검증 결과를 문서화한다. 아직 검증하지 않은 발음 검사 등을 통과한 것처럼 처리하지 않는다. 판정 불능도 자동 공개의 근거가 될 수 없다.

기본 실패 처리 제안:

1. 품질 문제는 사전 설정한 유한한 재생성 횟수와 남은 예산 안에서만 재시도한다. 구체적인 횟수는 비용 검증 후 정한다.
2. 한도·권한 오류는 재생성 재시도 대상이 아니다. 제출 결과를 모르는 네트워크 오류는 기존 작업 상태부터 조회한다.
3. 기준을 충족하지 못하거나 비용이 부족한 결과물은 공개를 보류하고 원인을 알린다. 주간 수량을 맞추려고 미완성·미검사 파일을 공개하지 않는다.
4. 성공한 곡·장면·업로드 기록을 보존한다. 재실행은 실패 지점부터 이어가며 같은 결과물을 중복 생성·게시하지 않는다.
5. 두 언어 중 한 편만 통과한 경우에는 ‘끝나는 대로 공개’ 원칙에 따라 그 편을 먼저 공개하고, 실패한 편의 상태를 별도 보고한다.
6. 알림 전송 실패 때문에 영상 제작·공개를 다시 실행하지 않는다. 알림만 별도로 재전송할 수 있게 한다.

## 8. 완료·실패 알림

사용자는 성공 알림과 실패·보류 알림을 모두 원하며, 카카오톡 또는 이메일을 선호한다. 이후 추천 방향으로 진행하도록 요청했으므로 **이메일을 기본 경로로 설계**하고 카카오톡은 선택적 확장으로 남긴다. 두 채널 동시 발송을 필수로 요구한 것은 아니다.

| 상황 | 알림 내용 |
|---|---|
| 정상 완료 | 주제·언어, 공개된 영상 링크, 생성·재사용 결과, 실제 사용 크레딧, 확인 가능한 남은 사용량 |
| 일부 성공 | 공개된 결과와 보류된 결과를 구분하고 각각의 상태·사용량 보고 |
| 실패·공개 보류 | 원인, 완료된 단계, 보존한 결과, 재시도 여부, 다음 자동 실행 또는 필요한 조치 |

메일은 영상 파일 첨부 대신 링크와 간결한 요약을 기본으로 한다. 수신 주소와 최초 연결 인증은 운영 설정 시 확정한다. 비밀번호·토큰을 채팅이나 문서에 받지 않고 안전한 환경변수 등으로 설정한다.

카카오톡은 공식 ‘나에게 보내기’ 방식의 앱 설정·로그인·동의·토큰 관리 가능성을 별도로 검증한다. 유료 알림톡 계약을 자동으로 추가하지 않는다.

## 9. 고려한 운영 방식과 선택

| 방식 | 장점과 제약 | 인터뷰 결과 |
|---|---|---|
| Suno 수동 생성·선택 + 후속 자동화 | 기존 제작 경로를 활용할 수 있지만 매번 사용자 작업이 필요함 | 사용자가 완전 자동을 요구해 제외 |

| Suno를 유지한 전체 무인 자동화 | 사용자가 원하는 방식. 허용된 자동 생성 연동 경로와 구독 내 지속 가능성이 아직 미확정 | **요구사항으로 선택. 실현 가능성은 검증 전** |

사용자가 선택한 것은 세 번째 목표 구성이다. 이것을 구현이 검증된 기술 경로로 혼동하지 않는다. 첫 번째나 두 번째를 자동 대체안으로 실행하지 않는다.

## 10. 기존 저장소와의 차이

현재 파일에서 확인한 내용과 이번 인터뷰의 새 결정을 구분한다. 이 문서를 작성하면서 기존 설정·제작 코드·원 지시서를 변경하지 않았다.

| 현재 기준 | 새 요구사항 |
|---|---|
| `config.languages = ["en"]`, ep11만 한국어 예외 | 채널 전체에 한국어·영어를 병행하고 재생목록으로 구분 |
| 기본 기획 영상 2~3분 | 곡별 1~2분 |
| Suno 파일 수동 생성·전달 | Suno 고정으로 음원 생성까지 무인화 희망. 연동 미해결 |
| 언어·곡에 맞춘 컷 및 립싱크 제작 | 주제별 공통 영상, 립싱크 없음, 언어별 음원·단어 합성 |
| 제작 중 여러 사용자 승인 단계 | 정상 운영은 사용자 개입 없이 자동 검사·진행 |
| 수동 실행하는 게시 워크플로 및 예약 공개 인자 | Mac에서 월·금 09시 정기 제작, 검사 후 즉시 공개 |
| 운영자 완료·실패 알림 구현 없음 | 이메일 기본 알림, 카카오톡 선택적 연동 |

활용 가능한 기존 구성: `song_track.py`, `hf_jobs.py`, `fetch_assets.py`, `build.py`, `upload.py`, `estimate_credits.py`, 생성 기록·중복 업로드 방지 구조. `song_track.py`의 파일 가져오기 기능은 Suno 자동 생성 기능이 아니다.

원 지시서 `ORIGINAL_BRIEF.md`는 수정하지 않는다. 구현 시 변경된 정책은 최신 결정 문서와 관련 설정·런북에 일관되게 반영하고, 이미 공개된 에피소드나 승인된 라이브러리를 소급 변경하지 않는다.

## 11. 완료 기준과 검증 계획

기획 문서 작성 완료와 실제 자동화 운영 완료를 구분한다. 구현 완료를 주장하려면 다음 증거가 필요하다.

1. Suno 고정·허용된 연동·추가 결제 없음이라는 조건에서 음원 생성과 다운로드가 무인으로 동작한다.
2. 테스트 제작 묶음 하나에서 같은 주제의 한국어·영어 두 곡과 공통 영상 한 편을 만들고, 언어별 최종 파일 두 개를 출력한다.
3. 최종 파일은 각각 60~120초이며 대응 학습 단어가 1~3개이고 화면과 음성이 맞는다. 공통 장면은 언어별로 중복 생성하지 않는다.
4. 정기 실행은 `Asia/Seoul`의 월·금 09시를 기준으로 하며, 검사 통과 후 올바른 채널·재생목록에 게시한다. 초기 검증에서는 비공개 테스트로 업로드·조회 흐름을 먼저 확인한다.
5. 공개 기능의 실제 권한을 확인하고, 업로드 요청 성공과 실제 공개 완료를 구분해서 기록한다.
6. 재시작·네트워크 오류·중복 실행에서도 이미 성공한 생성과 업로드를 중복 과금·중복 게시하지 않는다.
7. 사용량 부족, 판정 불능, 품질 실패, 인증 실패에서는 공개를 보류하고 기존 성공분을 보존한다. 추가 구매가 발생하지 않는다.
8. 완료·부분 성공·실패 알림을 지정한 수신자에게 전달하고, 알림 재시도가 콘텐츠 재생성을 유발하지 않는다.
9. 스크립트를 수정한 경우 저장소 규칙에 따라 `bash momo/tests/run_all.sh`를 통과한다. 음원·영상 품질은 코드 테스트와 별도로 실제 샘플로 검증한다.

구현 담당자에게 맡길 결정: 파일·작업 식별자, 스케줄러 구현, 상태 저장 방식, 타이밍 보정, 비용 내 재시도 횟수, 검사 도구와 수치 기준, 메일 인증 방식. 이러한 결정은 도구 고정·예산·공개 정책·개인정보 취급 제약을 완화할 권한을 뜻하지 않는다.
